# Integration Status

## Scope

This document records the integration boundaries that are present in the repository after cleanup. It is intentionally explicit about what is working and what is not implemented, so a deployment does not imply a backend that does not exist.

## Frontend

- `src/main.tsx` mounts `App` into the root element.
- `src/App.tsx` provides React Query, tooltips, toasts, motion preferences, and hash-based routing.
- The routes in `src/App.tsx` cover home, portfolio, services, pricing, about, blog, and contact pages.
- `src/config/site.ts` is the single place for routes, company details, and social/contact links. Update this file when brand or contact details change.
- `src/lib/index.ts` contains typed page content such as services, pricing packages, testimonials, and blog posts.
- `vite.config.ts` supplies the route-messaging bridge used by the preview host. It is enabled only when `VITE_ENABLE_ROUTE_MESSAGING=true`.
- `npm run build` is the production integration check for the frontend.

## Root directories and configuration

- `public/` contains files copied directly to the site root. `favicon.ico` is used by browsers and `robots.txt` is used by crawlers.
- `dist/` is generated by `npm run build`. It is not source code and must not be committed or edited manually.
- `node_modules/` is generated by `npm ci`. It is not source code and must not be committed.
- `components.json` configures the shadcn/ui generator. It is not needed at runtime, but it keeps future component additions consistent.
- `eslint.config.js` configures linting.
- `vite.config.ts` configures the dev server, React plugin, Tailwind Vite plugin, aliases, and preview route messaging.
- `tsconfig.json`, `tsconfig.app.json`, and `tsconfig.node.json` configure TypeScript for the app and Vite configuration.
- The old `postcss.config.js` was removed because this project uses Tailwind CSS through `@tailwindcss/vite`, not the PostCSS adapter.

## Contact flow

The contact form validates data in the browser with React Hook Form and Zod. A valid submission opens a pre-filled WhatsApp message using the configured contact link in `src/config/site.ts`. No form data is persisted by this repository.

This means:

- WhatsApp hand-off is the current working enquiry integration.
- There is no application API, database write, email service, or authentication flow.
- Browser popup blocking can prevent WhatsApp from opening; users can use the direct WhatsApp link shown on the contact page.
- Unknown routes render the shared `src/pages/NotFound.tsx` page instead of an empty application shell.

## Backend status

There is currently no backend implementation in this repository. The former Supabase test scaffold and unrelated Stripe examples were removed because they referenced missing functions and clients and could not be run or integrated with the frontend.

Do not configure a backend health check or claim database/edge-function support until an actual service is added under source control with:

1. A typed API module under `src/api/`.
2. Environment variable documentation and a safe local example.
3. A deployed function or server implementation.
4. Frontend error/loading handling for the API call.
5. Automated tests that run in the repository's supported toolchain.

## Verification checklist

Run from the repository root:

```bash
npm ci
npm run lint
npx tsc --noEmit -p tsconfig.app.json --strict
npm run build
```

The commands above validate the frontend end to end from source compilation through production bundling. Backend checks are intentionally not listed because no backend exists in the current codebase.

## Remaining work

- Add a backend only if enquiry persistence, email notifications, authentication, or an admin dashboard is required.
- If a backend is added, update this document and the README in the same change, then add a runnable integration test.
